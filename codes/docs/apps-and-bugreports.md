# 应用管理与 Bugreport

## 应用管理

“应用与进程”页面包含“应用管理”和“关注应用”两个 Tab。两个 Tab 复用同一份设备应用快照、同一种应用卡片和同一个详情页；关注列表是 `watched_packages` 手动星标与 `process_package_keywords` 关键词匹配的并集，卡片显示关注来源。页面改名不改变稳定存储域：原有 `processes` key、`process_package_keywords` 和 `app_launches` 继续使用。

### 列表读取

- `app/app_manager.py` 使用 `pm list packages -f -U` 批量读取包名、APK 路径和 UID。
- 使用 `pm list packages -3` 区分用户应用与系统应用。
- 使用一次 `ps -A` 建立包名到 PID 的映射。
- 应用管理搜索同时匹配包名和当前快照中的 PID，PID 搜索只做前端过滤，不增加 ADB 调用。
- 列表阶段禁止逐包调用 `dumpsys package`，避免应用较多的设备刷新过慢。
- 版本、安装时间、Enabled 状态、签名和 APK 路径在打开单个应用详情时按需读取。
- 卡片中的应用类型、UID、PID 和平台签名使用独立间隔展示。平台签名默认不批量读取，点击卡片文字后只查询该应用，并在同一设备的页面切换和列表刷新期间保留结果。
- 关注应用卡片不额外展示关注来源，手动星标与关键词匹配仍共同决定该列表的内容。
- 桌面卡片中的运行状态与详情、启动、停止按钮保持垂直居中和同一水平线。

### 应用操作

- 未配置特殊拉起命令时，通过 `cmd package resolve-activity --brief` 获取 Launcher 入口，再使用 `am start -n` 启动。
- 没有 Launcher 或需要特定 Activity、Action、Extras 时，在统一应用详情中维护 `app_launches` 特殊拉起配置；已有配置继续无损复用。
- 详情进入特殊拉起配置时使用同一个弹窗壳的视图栈保存原详情 DOM；关闭、取消、保存或删除顶层配置后直接恢复详情，不重新请求或重建详情内容。
- 应用详情在加载、Pull APK 和证书计算期间保持稳定尺寸：加载使用内容骨架，Pull 按钮与进度条即时反馈，证书结果在预留区域内展示。
- 安装时间与更新时间并排展示；证书区域预留单个常见签名的完整空间，不在结果卡片内增加第二层滚动。
- 特殊拉起配置使用独立的紧凑尺寸；删除、取消和保存在同一底部操作栏，返回详情时恢复原 DOM、滚动位置和尺寸。
- 特殊拉起命令为空时，可按 Tab 直接采用输入框中的建议命令，并立即刷新执行预览。
- 强制停止使用 `am force-stop`。
- 清除数据、禁用和卸载必须由用户明确确认。清除和启用/禁用作用于设备当前 Android 用户，不能固定操作 user 0。
- Pull APK 只拉取 `base.apk`，先写入 Device Explorer 的受管下载暂存区并通过非空校验，再由桌面下载对话框让用户选择保存位置；不会自动加入 APK Center。Split APK 支持留待后续版本。
- 证书 SHA-256 在应用详情内原位显示，不打开第二层弹窗；点击具体摘要可复制到剪贴板。
- 应用列表来自设备实时状态，不写入用户配置。

## Bugreport

Bugreport 位于“设备工具 → Bugreport采集”，与“日志Pull”和“设备文件”处于同一层级。它与录屏的 `--bugreport` 信息叠加不是同一功能。

### 数据目录

```text
adb-tools/bugreports/
├── files/       # 完成的 ZIP
└── runtime/     # 正在执行的临时任务
```

`bugreports` 是新的稳定存储 key，但当前没有配置 JSON。它不读取、迁移或重写 `device_logs` 数据。

### 任务模型

- 同一 Workbench 服务进程只允许一个 Bugreport 任务。
- 启动时固定使用当前已验证设备 serial。
- ADB 先将结果写入独立临时目录；只有退出码成功且存在非空 ZIP 时，才移动到 `files/`。
- 取消操作优先向 macOS/Linux 子进程发送中断信号，Windows 终止进程。
- 任务完成、失败或取消后清理临时目录。
- 页面轮询任务状态，因此采集期间可以看到耗时，也可以离开页面后再返回。
- 下载和删除只接受 `files/` 下重新验证的单层 `.zip` 文件 ID。
- 页面提供刷新、下载和删除，不提供打开受管数据目录的入口，避免用户绕过软件直接修改文件。

## 数据兼容

- “进程管理”改名不移动原配置文件。
- “日志Pull”与“Bugreport采集”的页面层级变化不改变 `device_logs`、`bugreports` key 和原有配置。
- 新增 Bugreport 目录不会扫描、移动或删除任何已有用户资产。
