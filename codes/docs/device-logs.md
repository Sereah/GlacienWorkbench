# 设备日志 Pull

前端入口位于“设备工具 > 日志 Pull”。它与屏幕捕获、设备文件共用二级功能页，但后端 API、配置文件和 Pull 输出规则保持独立。

设备日志页用于扫描 `adb-tools/device-logs/sources.json` 中命名的设备日志源，并将用户勾选的文件通过 ADB Pull 到系统下载目录中新建的 `device-logs-<当前时间>/` 文件夹。时间段是可选筛选条件：不填写时展示全部符合 `file_pattern` 的文件；填写后只返回可靠时间与范围相交的文件并默认勾选。若自动识别对整个来源均失败，则回退为展示全部文件供用户手动选择。

扫描使用一次设备端 `find -exec toybox stat ... {} +` 批量获取当前目录普通文件的路径、大小和修改时间，避免文件数量增加时产生逐文件 ADB 往返。字段使用不可见分隔符并从右侧解析，兼容文件名空格且不经过宿主机 Shell。

桌面布局中，扫描结果列表是位于“已选择文件”工具栏和 gzip/Pull 操作栏之间的独立滚动区；列表增长不得带动整个页面滚动，底部 Pull 操作始终保持可见。

## 配置模型

`device_log_sources` 的每一项包含：

- `device_directory`：设备端绝对目录，不能是 `/`，不能含 `..`。
- `file_pattern`：当前目录下 basename 的 glob，例如 `android_log.*.gz`。
- `archive_type`：`none` 表示普通文件，`gzip` 表示允许在用户勾选“若日志源为 gzip，Pull 后自动解压”时解压。它只控制 Pull 后处理，不影响目录扫描、文件匹配或时间识别；即使配置为 `gzip`，未勾选时也会保留原始压缩包。
- `time_rule`：可选时间识别；`none` 时仍能扫描和手选。

时间类型：

- `none`：不识别时间。
- `mtime`：使用设备文件修改时间，可信度取决于车机系统时间。
- `filename_auto`：推荐选项。自动识别文件名中的常见 14 位时间、带分隔符日期时间，以及 10 位/13 位 Unix 时间戳；支持单时间、明确起止时间和本地时间 + UTC。无需填写正则，单个文件识别失败时标记为时间未知，整个来源均无法识别时等同于“不识别时间”，文件仍可手动勾选。

时间含义 `archive_start` / `archive_end` 会用相邻的高可信度归档点推导覆盖区间；低可信度或时间未知文件始终保留在列表中，但不会自动勾选。

普通用户只需填写来源名称、设备目录和文件匹配，并选择“自动识别文件名（推荐）”。界面不再提供手写正则、文件名起止时间或本地时间 + UTC 配置；旧配置读取时会迁移到自动识别。

## 安全边界

- 浏览器只能提交日志源名称，后端每次从当前 settings 重新读取设备目录。
- 扫描只接受单层安全 basename，Pull 前重新扫描并建立最新白名单。
- ADB Pull 使用参数数组和已验证 serial，不经本机 Shell。
- 每次 Pull 在系统下载目录直接创建 `device-logs-YYYYMMDD-HHMMSS/`，选中的文件平铺其中，不生成 manifest JSON。浏览器不能指定路径。macOS 使用 `~/Downloads`，Windows 使用系统 Downloads Known Folder，Linux 优先使用 `XDG_DOWNLOAD_DIR`。
- 中途失败时保留本次文件夹以及已经成功拉取的文件，不额外生成状态文件。
- Pull 成功后页面在结果状态右侧显示“打开文件夹”，后端仅接受本次返回的 `device-logs-<时间>` 文件夹名，并重新验证它位于系统下载目录后再调用文件管理器。
- `logs/` 是用户数据和升级保护目录，打包与升级不得删除或覆盖。

## 双时间文件名示例

对于 `android_log.24223.20260921183506_20260921103506.gz` 这类通用示例，自动识别会把两个相差 8 小时的字段判定为本地时间与 UTC 的同一时刻，主展示时间使用配置的 `Asia/Shanghai`。年份早于 2020 的条目标记为低可信度，不参与时间筛选。
