# Logcat、SSE 与前端

## 主题配置

- `web/themes.json` 是全部内置主题、schema 和字段说明的唯一来源，`glacien` 是默认主题。`tokenGuide` 使用可读字段名说明每个颜色的 CSS 变量、含义和对应控件。
- 标准 JSON 不支持注释，因此说明必须写在 `guide`、`description` 和 `usedBy` 字段中，不能加入 `//` 或块注释。
- `defaultTheme` 既是默认选择，也是其他主题缺失颜色的回退来源；CSS `:root` 仍保留基础颜色，防止主题文件损坏或加载失败时出现不可用界面。
- `tokenGuide.fallbackToken` 用于新增语义颜色的向后兼容：旧用户主题缺少新字段时优先继承该主题自己的通用颜色，而不是退回内置紫色。重点标题边框、设备选择边框、粘性操作栏背景/边框和重点卡片边框均使用该机制。
- 主题选择结果保存到用户数据 `runtime/themes.json` 的 `selected_theme`，重启或 WebEngine Profile 重建后仍会恢复。首次升级若服务端尚无该字段，可从旧 `localStorage` 偏好接入并写回用户数据；加载时只接受安全主题 ID、`dark` / `light` 模式和受限 CSS 颜色格式，不能把 JSON 内容拼接成 `<style>`。
- `app/themes.py` 通过 `GET /api/themes` 合并内置主题与用户数据 `runtime/themes.json`。导入主题必须经过服务端 ID、字段和颜色格式校验，再用 `storage.write()` 原子保存；全部内置主题都不能覆盖或删除。
- 主题悬浮窗支持导入、导出以及删除用户主题。导出内容会展开继承后的完整颜色并保留 `tokenGuide`，可直接修改后重新导入；同 ID 用户主题覆盖需要确认，删除当前主题后回退到 `glacien`。主题不属于规则包。
- 日志高亮固定使用紫、青、绿、黄、橙、红六套配色，不属于界面主题；切换或导入主题不能改变高亮色。实时和离线日志的高亮透明度仍是各自的显示偏好。旧主题中的 `logHighlight*` 和 `textOnHighlight` 字段仅为导入兼容而忽略，重新导出时不再包含。

- 实时日志流程：必须先选择已保存规则；后端校验该规则有整体过滤词后，才启动 `adb logcat` 子进程、读取缓冲区回放并发送 SSE 实时行。不得恢复空规则或“全部日志”入口，否则大缓冲区会拖慢浏览器。
- SSE 日志保持逐条实时接收，前端通过 `requestAnimationFrame` 按帧合并 DOM 更新。每帧最多渲染 250 条，使用 `DocumentFragment` 一次插入、统一裁剪并只执行一次自动滚动；页面保留最近 1300 条，接收总数独立累计。高亮规则在会话建立时预处理，批量内每条日志仍按原规则实时高亮。停止监听时刷新剩余队列，清空显示、清空设备日志或切换会话时必须丢弃旧队列，防止旧日志重新写回。
- ADB 输出使用 UTF-8 `errors=replace`；不要恢复严格解码。
- 日志过滤：`include_any` 是 OR，`include_all` 是 AND，`highlights` 指定颜色。高亮词与筛选词相互独立，只对已经通过筛选的日志行上色，不会扩大日志范围。
- 实时和离线日志规则可用 `priority_constraints` 为某个包含关键词设置最低 Logcat 级别。限制只在该关键词命中时生效：同一 `include_any` 条件内未受限的关键词仍匹配全部级别；一行同时命中普通关键词和受限关键词时，普通关键词可以独立使该条件通过。级别顺序为 `V < D < I < W < E < F`，Assert 按 Fatal 处理。受限关键词必须存在于 `include_any` 或 `include_all` 中，不能来自 `exclude_any`。旧规则缺少该字段时使用空数组，不改变原有行为。
- 关键词级别限制依赖 `adb logcat -v threadtime` 的标准头。实时回放、实时流、实时导出、离线高速 `rg` 扫描和浏览器 Worker 必须保持相同语义；无法解析标准头的行不能满足受限关键词，但仍可由普通关键词命中。普通关键词不会因为其他关键词设置了级别限制而丢失低级别日志。复制为 grep/rg 仍只复制通用关键词条件，不携带 Logcat threadtime 专属的级别限制。
- 实时日志规则与离线日志统一使用连续 `filters`：每条条件可选 `include_any`、`include_all` 或 `exclude_any`，条件之间始终为 AND。旧规则的 `include_any` / `include_all` 在读取时自动转换为条件数组，下次保存写入新格式。
- 进程筛选位于实时日志页面，不属于分析方案，只影响本次监听和导出。开始监听和导出时，后端通过 `adb shell ps -A` 精确匹配 NAME 列并解析当前 PID，再从 `threadtime` 日志头解析 PID；PID 过滤先于关键词过滤。目标进程未运行时应明确报错。旧规则中的 `process_name` 字段继续保留，旧客户端仍可使用；新页面提交的单次参数会明确覆盖它，空值表示不过滤进程。
- 基础模式直接使用条件行增删和编辑；表达式模式中 `(a | b)` 表示包含任一，`(a & b)` 表示包含全部，`!(a | b)` 表示排除任一，条件之间以 `&` 连接。单关键词包含全部使用 `all(a)` 保持无损；含空格、`|` 或 `&` 的关键词使用双引号。表达式本身不作为 Shell 或正则执行。
- 实时与离线表达式编辑器都提供“复制为 grep”和“复制为 rg”。复制结果是不包含日志来源的标准输入过滤管道，可接在 `adb logcat`、`cat` 等命令后；包含全部会展开为连续管道，排除任一使用反向匹配，`*` 转换为正则通配，并保持页面筛选默认不区分大小写的语义。
- 双模式面板自身设置了 flex/grid display，因此必须为基础和表达式面板显式声明 `[hidden] { display: none !important; }`；否则作者样式会覆盖浏览器的 hidden 默认样式，表现为点击切换无反应。编辑器及其 flex 子项必须设置 `min-width: 0` / `max-width: 100%`，长关键词不能撑出页面。
- 实时日志规则面板按查询构建器组织：规则名称独占一行；基础模式与离线日志一样使用连续条件行；表达式模式使用全宽 Query 编辑器并实时显示解析数量和匹配方式；高亮规则位于独立的默认折叠区。不要恢复把规则名、模式和长关键词横向塞入同一行的旧布局。
- 实时与离线日志共用过滤配置的视觉组件：`createLogFilterRow()` 生成统一的模式、关键词和删除控件；`log-filter-builder` 提供卡片与标题栏；`createLogHighlightSection()` 提供默认折叠高亮区；saved/dirty 状态复用 `log-rule-draft-state`。两边只保留表达式、来源、进度、执行与导出等功能差异，不得再复制第二套条件行或高亮区样式。
- 实时与离线日志共用过滤配置的视觉组件：`createLogFilterRow()` 生成统一的模式、关键词和删除控件；`log-filter-builder` 提供卡片与标题栏；`createLogHighlightSection()` 提供默认折叠高亮区；saved/dirty 状态复用 `log-rule-draft-state`。两边可保留表达式、来源、进度和导出等功能差异，但不要复制第二套条件行或高亮区样式。
- 在线与离线日志页面是结果工作台：页面保留当前过滤方案入口与运行控制，实时日志另在页面上提供单次进程筛选。条件、高亮、方案选择/新建/删除/保存都在共享悬浮窗编辑。方案面板必须在关闭时放回隐藏宿主节点，不能复制编辑器或丢失既有事件绑定；两套方案弹窗的方案栏、条件编辑器、添加条件按钮、高亮区和保存区保持一致。
- 已加载的实时日志规则必须维护语义 baseline。规则名、匹配方式、关键词/表达式和高亮词变化时显示“已修改，未保存”；新规则显示“未保存的新规则”，表达式解析失败显示“表达式有误”。切换日志规则、新建规则、关闭方案悬浮窗、离开日志页、关闭页面前必须确认是否丢弃，纯粹切换基础/表达式显示模式不应标记修改。
- 前端 `state.logs` 持有 EventSource，停止/保存规则时必须关闭旧连接。未选择保存规则时“开始”和导出按钮必须禁用；后端也必须拒绝空 `preset`，不能只依赖前端。
- “清空显示”只清空浏览器日志节点和页面计数，不访问 ADB、不停止 SSE，设备离线时也必须可用。“清空日志”会先关闭当前 SSE，再通过受设备选择校验的 `adb logcat -b all -c` 清空设备全部 Logcat 缓冲区，同时清空页面；此前正在监听时，清理完成后自动重新建立当前过滤方案的 SSE。每次监听使用递增会话编号，旧 EventSource 的在途回调必须被忽略，避免清空后旧日志重新写回页面。
- 设备轮询只能刷新设备状态；重新连接时刷新页面，但不要自动重建正在运行的日志会话。
- 离线日志页有两种明确来源模式。浏览器兼容模式使用 File API 在本地读取用户选择的单个、多个日志文件或文件夹，不向后端提交日志正文或本地路径；选择来源只保留文件句柄、相对路径和大小，点击过滤后由 `web/offline_log_worker.js` 分块解码和匹配，主线程只保留命中行。它不按扩展名筛选，跳过含 NUL 字节或 gzip 文件头的疑似二进制文件。页面把模式说明与来源状态合并为一行，为日志输出区释放高度。
- 多文件过滤结果按“相对文件名自然升序 + 文件内行号升序”排列，`log.9` 位于 `log.10` 之前。高速 `rg` 和浏览器兼容模式保持相同语义，页面与导出共用这份顺序。默认不解析或猜测正文时间，避免未知时间格式、多行堆栈或 uptime 日志被错误重排。
- 高速本地来源模式将命名绝对文件或目录路径存入当前 `local-tools/offline-logs/config.json` 的 `offline_log_sources`；桌面宿主通过 QWebChannel 暴露的系统文件和目录选择器产生路径，普通浏览器启动保留手工输入兼容。目录来源保存后由 `/api/offline-logs/archives` 检测压缩日志；前端展示清单并确认后，`/api/offline-logs/extract` 仍必须校验 `confirmed=true`。解压先在压缩包所在目录的隐藏临时区完成，全部内容安全就位后删除原压缩包；同名冲突或失败必须回滚展开内容并保留原包。单独选择压缩文件时必须提示改选所在目录，避免解压后来源路径失效。必须拒绝目录穿越、绝对路径、链接、特殊文件、过量文件、过大内容和异常压缩倍率。过滤阶段只提交来源名称和筛选条件，由后端按配置白名单调用 `rg --json --pcre2`，不得再次检测压缩包或接受任意路径。`/api/offline-logs/status` 实时返回当前进程能否找到 `rg`；不可用时禁用高速模式并提示安装。
- 实测：E68 runlog（175 文件、约 4.1 GiB）经 `/api/offline-logs/query` 用 `21:59` 查询返回 6,425 行，后端 `rg` 用时约 1.65 秒。
- 离线过滤必须由用户点击“过滤”触发，不能在输入过程中重复扫描文件。Worker 应报告已扫描文件数、已读取字节和命中数量，并支持停止；它使用连续筛选条件：每条条件可选包含任一、包含全部或排除任一，所有条件之间均为 AND，因此后加条件只会缩小已有结果。高速模式将关键词级别限制编码进安全生成的 PCRE2，并在解析 `rg` 结果时再次校验；浏览器模式在 Worker 内执行同样的级别判断。输出必须带来源相对路径和行号。大结果只分页渲染，下载仍包含全部匹配行。
- 离线分析方案存于当前 `local-tools/offline-logs/config.json` 的 `offline_filter_presets`。每个方案保存每条条件的 `mode` 与 `terms`、可选 `priority_constraints`、六色 `highlights` 与 `highlight_case_sensitive`；不得保存浏览器选择的本地日志路径、日志正文、字体、透明度或导出文件名。旧版仅含条件数组的预设仍可导入。
- 已导入方案的筛选条件、颜色词、颜色大小写和方案名称出现改动时，前端必须显示未保存状态；在切换分析方案和离开页面前提示确认，避免静默丢失。用户确认丢弃时，必须实际恢复已保存方案内容；不能只清除提示而保留被修改的表单。
- 离线分析方案和广播的“新建”必须使用选择器外的明确按钮；选择器仅列出已保存项，避免空选项同时承载“取消选择”和“新建”两种语义。
- 离线字体与高亮透明度使用独立的浏览器本地显示偏好；六色高亮关键词与“颜色区分大小写”属于可保存的离线分析方案。两者都不能影响实时日志会话或其 `state.logs` 生命周期。大小写开关只影响颜色高亮，不改变离线筛选条件的匹配语义。
- 桌面端日志输出默认占据工作台的剩余可视高度，并在自身容器内滚动；实时和离线日志都可拖动输出框底部手柄增减高度，偏好仅保存在当前浏览器本地。长 APK、资源和进程列表同样只在各自容器内滚动。小屏幕允许回退为页面滚动，不能以固定高度遮挡必要控件。
- 离线分析的开始过滤、导出文件名和导出结果属于扫描方式与来源上下文，应放在该运行区域，不占用结果展示区；日志方案悬浮窗应使用更宽的工作区宽度以容纳条件与高亮编辑。
- 前端代码当前集中在 `web/app.js`；新增较大页面逻辑时优先拆出按页面或功能组织的文件。
