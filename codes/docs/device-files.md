# Device Explorer

“设备工具 > 设备文件”提供接近 Android Studio Device Explorer 的设备端文件浏览能力。默认打开 `/sdcard`，可通过路径栏、面包屑和上级按钮逐层进入设备目录。

## 支持的操作

- 浏览目录：目录优先显示名称、大小、修改时间和权限；每次最多显示 300 项。目录元数据通过一次设备端批量 `stat` 读取，避免按条目反复发起 ADB 调用；失效软链接会跳过，不阻塞根目录。
- Pull 文件：Pull 当前目录重新扫描确认存在的单个普通文件。文件先保存到固定的 `adb-tools/device-tools/downloads/<设备序列号>/<时间>/`，再由浏览器下载。
- Pull 文件夹：Pull 当前目录重新扫描确认存在的目录。后端先 `adb pull` 整个目录到临时子目录，再用 `shutil.make_archive` 打包成 zip、删除展开的原始目录，只保留 zip 供浏览器下载。zip 名称使用条目名的 ASCII 安全 slug，确保通过下载 ID 白名单校验。
- 批量 Pull：列表支持多选和全选。同一目录内选中的文件与文件夹会在一次安全校验后逐项 Pull，并统一打包为一个 zip 下载。
- 上传文件：浏览器选取一个文件后 Push 到当前设备目录，目标始终是明确的“当前目录/原始文件名”。同名文件需要再次确认覆盖；支持零字节文件。
- 上传文件夹：浏览器通过 `webkitdirectory` 选取目录，前端按文件逐项上传，设备端在当前目录下保留顶层文件夹及内部相对层级。开始前统一确认，已有同路径文件会覆盖，但不会删除设备端目录中的其他内容；单项失败不阻塞剩余文件，结束后汇总结果。浏览器不会返回纯空目录，因此无法还原其中的空目录。
- 新建文件夹：在当前已验证目录中创建一个文件夹；同名文件或文件夹存在时拒绝创建。
- 新建文件：在悬浮窗中填写文件名和不超过 1 MiB 的 UTF-8 文本内容，也可留空创建空文件。同名普通文件需要二次确认覆盖，同名文件夹不能覆盖。文本先写入受管临时文件，再通过 `adb push` 写入设备，内容不经过 Shell 拼接。
- 文件预览：点击普通文件名称后在悬浮窗中读取预览。最多读取前 256 KiB，使用 UTF-8 严格解码并检测 NUL 和异常控制字符；文本安全转义后展示，非文本文件只显示按文件头识别的类型、大小和 Pull 入口。
- 删除文件：删除普通文件用 `rm -f`；前端确认后仍由后端检查 `confirmed`。
- 删除文件夹：递归删除目录用 `rm -rf`，属于破坏性操作，前端使用强化确认文案，后端同样检查 `confirmed`；仍通过参数数组调用 ADB，不经宿主机 Shell。
- 批量删除：列表支持多选和全选；操作前统一提示选中数量及文件夹数量。后端重新扫描同一父目录后逐项删除，并返回成功与失败明细。

## API

- `GET /api/device-files/list?path=<绝对路径>&serial=<serial>`：列出一层目录。
- `POST /api/device-files/pull`：Pull 已验证的单文件，或将已验证的目录打包为 zip 后返回。
- `POST /api/device-files/pull-batch`：Pull 同一目录内已验证的多个条目，并打包为一个 zip。
- `POST /api/device-files/upload`：multipart 上传当前设备目录；可携带经过后端逐段校验的 `relative_path` 保留文件夹层级。
- `POST /api/device-files/create-directory`：在当前设备目录创建已校验名称的文件夹。
- `POST /api/device-files/create-file`：创建 UTF-8 文本文件；覆盖已有普通文件前要求确认。
- `POST /api/device-files/preview`：安全读取普通文件的有限内容并返回文本或二进制识别结果。
- `POST /api/device-files/delete`：二次确认后删除单文件（`rm -f`）或递归删除目录（`rm -rf`）。
- `POST /api/device-files/delete-batch`：二次确认后逐项删除同一目录中的多个已验证条目。
- `GET /api/device-files/download?id=<受控下载ID>`：下载已 Pull 的本地文件或打包 zip。

## 安全边界

- 所有设备操作均先验证浏览器选择的 ADB serial。
- 设备路径只能是规范绝对路径，拒绝 `.`、`..`、换行和 NUL；单文件名不允许路径分隔符。文件夹上传的相对路径会逐段执行相同校验，并拒绝绝对路径、反斜杠、空分段和路径跳转。
- Pull、删除和预览前会重新读取父目录，只处理最新列表中的条目，避免请求篡改或目录切换后的陈旧条目。文件 Pull/删除/预览仅接受普通文件；目录 Pull 打包 zip，目录删除为递归删除。
- ADB 通过 `android.device_adb()` 的参数数组调用，不经宿主机 Shell；文件夹上传所需的 `mkdir -p` 和递归删除的 `rm -rf` 亦然。
- 本地 Pull 输出、打包 zip 和临时上传文件均固定在 `adb-tools/device-tools/downloads/`；浏览器不能传入本机输出路径。该目录是系统用户数据，不进入程序包。
- `/data` 等受权限限制路径由设备实际权限决定；读取失败必须向界面返回明确错误，不能伪装为空目录。
